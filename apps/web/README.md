## 🚀 Project Structure

Inside of your Astro project, you'll see the following folders and files:

```text
/
├── public/
├── src/
│   └── pages/
│       └── index.astro
└── package.json
```

Astro looks for `.astro` or `.md` files in the `src/pages/` directory. Each page is exposed as a route based on its file name.

There's nothing special about `src/components/`, but that's where we like to put any Astro/React/Vue/Svelte/Preact components.

Any static assets, like images, can be placed in the `public/` directory.

## 🧞 Commands

All commands are run from the root of the project, from a terminal:

| Command                   | Action                                           |
| :------------------------ | :----------------------------------------------- |
| `npm install`             | Installs dependencies                            |
| `npm run dev`             | Starts local dev server at `localhost:4321`      |
| `npm run build`           | Build your production site to `./dist/`          |
| `npm run preview`         | Preview your build locally, before deploying     |
| `npm run astro ...`       | Run CLI commands like `astro add`, `astro check` |
| `npm run astro -- --help` | Get help using the Astro CLI                     |

## ⚡ Performance

Hybrid rendering: marketing pages with no per-request state (`/`, `/about`, `/contact`, `/privacy`, `/terms`) are prerendered to static HTML at build time. Dynamic public routes (`/listings`, `/buildings/[slug]`, `/units/[id]`) stay SSR but set `Cache-Control: public, s-maxage=1800, stale-while-revalidate=86400` so Vercel / Cloudflare cache them at the edge. Authenticated routes (`/portal/*`, `/admin/*`, `/login`, `/maintenance`, `/schedule`, `/api/*`) stay SSR with `private, no-cache` (configured in `vercel.json` and `public/_headers`).

## Testing

Run from the repo root:

- `pnpm --filter @ar/web test` — Vitest unit tests (auth helpers, email render contract, data-layer fallback, logger, middleware, photo URLs).
- `pnpm --filter @ar/web test:e2e` — Playwright end-to-end specs (browse, a11y, maintenance submit, showing submit). Set `E2E_SUBMIT=true` to exercise the actual form submission paths against a configured backend.
- `supabase db execute < supabase/tests/rls.spec.sql` — RLS policy smoke tests against a `supabase db reset`-ed local database. See `supabase/tests/README.md` for details.

## PWA install

The Astro app ships as an installable Progressive Web App. Configuration lives
in `astro.config.mjs` (the `@vite-pwa/astro` integration) and the manifest at
`public/manifest.webmanifest`.

### What ships
- **Service worker** auto-generated by Workbox + the bespoke
  `public/sw-extra.ts` for the offline maintenance-request queue and Web Push.
- **Manifest** at `/manifest.webmanifest` with brand colors (`#0a58ca`) and
  PNG icons at 256/512 (and a 512 maskable variant).
- **Install prompt** on portal routes via
  `src/components/islands/InstallPrompt.tsx`. Dismissals are stored in
  `localStorage`. iOS Safari gets static "Add to Home Screen" guidance — iOS
  does not fire `beforeinstallprompt`.
- **Offline queue indicator** via
  `src/components/islands/OfflineQueueIndicator.tsx`.
- **Push opt-in button** via
  `src/components/islands/PushOptInButton.tsx`; subscriptions are stored in the
  `push_subscriptions` table via `/api/portal/push-subscribe`.

### Local development
PWA features (service worker, install prompt) require HTTPS or `localhost`.
`pnpm dev` runs on `localhost:4321`, which counts as a secure origin in
Chrome. PWA dev features are disabled (`devOptions.enabled: false`) — build a
preview to exercise the SW:

```sh
pnpm --filter @ar/web build
pnpm --filter @ar/web preview
```

### Cache safety
The Workbox config explicitly skips `/api/*`, `/portal/*`, and `/admin/*` so
no authenticated content is cached. See `astro.config.mjs` for the
`navigateFallbackDenylist` and the runtime-cache URL filters.

### Web Push
Generate VAPID keys once with:

```sh
npx web-push generate-vapid-keys
```

Place the values in `.env`:
- `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` / `VAPID_SUBJECT` (server)
- `PUBLIC_VAPID_PUBLIC_KEY` (browser; mirror of the public key)

Delivery from server code goes through `src/lib/push.ts`. Server delivery is
stubbed in MVP — UI subscribe/unsubscribe and the helper are in place; full
notification triggers will land alongside their feature work.

See `docs/superpowers/runbooks/pwa.md` for the full runbook.
